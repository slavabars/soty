# Soty (Соты)

Автономный, end-to-end зашифрованный текстовый мессенджер. Без аккаунтов, без
центрального сервера-хранилища. Работает офлайн (mesh из рук в руки) и онлайн
(прямой peer-to-peer), а для офлайн-доставки можно поднять собственный
relay-хост — только он не видит содержимого сообщений.

---

## Зачем это

- **Приватность по конструкции**: секреты рождаются на устройстве и никогда его
  не покидают. Хост, ретранслирующий сообщения, не может их прочитать.
- **Работает без интернета**: соседние устройства передают сообщения друг другу
  по BLE и Wi-Fi Direct — courier-доставка из рук в руки.
- **Работает с интернетом**: устройства встречаются напрямую (libp2p) без
  посредников, либо через трекер, который просто знакомит их адресами.
- **Никакого vendor-lock и облака**: свой relay-хост запускается на любой
  Linux-машине и обслуживает только ваш круг устройств.

## Как это работает

1. **Ключи и идентичность**. При первом запуске устройство генерирует пару
   Ed25519 (подписи) и пару X25519 (общий ключ). Приватные ключи остаются в
   хранилище устройства; наружу идёт только открытая часть.
2. **Знакомство**. Человек получает от собеседника invite-ссылку
   (`soty://invite?claim=...`) — подписанный конверт с публичными ключами и
   именем. По ней устройство добавляет собеседника в список контактов.
3. **Сообщение** — это цифровой конверт:
   - подписывается Ed25519 отправителем,
   - шифруется AES-256-GCM на общем ключе из X25519,
   - содержит противовес повторному воспроизведению (id + пробел по времени).
   Расшифровать может только владелец соответствующего приватного ключа.
4. **Доставка**:
   - онлайн — прямое p2p-соединение (включая identify-обмен, чтобы
     сопоставить ключи и адреса собеседника),
   - офлайн — mesh по BLE/Wi-Fi Direct (кто-то из сети отнесёт конверт),
   - офлайн-получателю — через relay-хост (см. ниже).
5. **Хранение на устройстве**. В историю попадают только конверты под ваши
   ключи: исходящие — под вашим Ed25519, входящие — под вашим X25519. Чужие
   нечитабельные конверты не заводятся в беседу. Старые записи прунятся:
   30 дней, батчами, с подписанными Merkle-корнями — то есть удаление можно
   доказать, а число конвертов на устройстве ограничено.
6. **Relay-хост (`dtm_host`)** в режиме «трекер + аварийный relay»:
   - принимает от устройств непрозрачные зашифрованные конверты и держит их
     до тех пор, пока получатель не заберёт,
   - ведёт `PEER_LIST` — каталог адресов, по которому устройства находят друг
     друга,
   - federated: хосты обмениваются backfill-запросами (анти-энтропия), так что
     сеть не зависит от одного хоста.

## Установка приложения (Android)

- `soty-release.apk` — релизный APK (minSdk 26+).
- Установка: скачать APK, разрешить установку из неизвестных источников
  («из этого источника» / «неизвестные приложения»), открыть файл.
- Первый запуск: приложение создаёт идентичность, показывает ваш
  invite-адрес; добавьте собеседника по его invite-ссылке.

   ```
   adb install soty-release.apk        # для sideloading-теста по adb
   ```

## Установка хоста (Linux, x86-64)

Бинарь `dtm_host.app` — самодостаточный исполняемый файл (без зависимостей):

```bash
chmod +x dtm_host.app
./dtm_host.app --listen 0.0.0.0 --port 3100            # по умолчанию 3000
```

Флаги:

| Флаг | Что делает | Пример |
| --- | --- | --- |
| `--listen` | адрес, на котором слушать | `0.0.0.0` |
| `--port` | TCP-порт | `3100` |
| `--db` | файл БД хоста (по умолчанию `host.db`) | `--db /srv/soty/host.db` |
| `--announce` | публичный URL `ws://.../ws` для баннера | `--announce ws://85.198.75.50:3100/ws` |
| `--peer` | пир-хост для федерации, повторяемый | `--peer 'ws://other:3100/ws\|pkHex'` |

В лог пишется баннер с адресом. Устройства подключаются по
`ws://<адрес>:<порт>/ws`; они используют хост как трекер (`PEER_LIST`) и как
аварийный relay для офлайн-конвертов. Хост хранит только непрозрачные
зашифрованные конверты (30-дневный прунинг с подписанными корнями) — прочитать
их не может никто, включая оператора хоста.

Запуск за systemd (мини-юнит):

```ini
[Unit]
Description=Soty relay host
After=network-online.target

[Service]
ExecStart=/opt/soty/dtm_host.app --listen 0.0.0.0 --port 3100
Restart=always
User=soty

[Install]
WantedBy=multi-user.target
```

## Ограничения и заметки

- Мессенджер текстовый: файлы/медиа не шлются.
- Минимальный Android: 8.0 (API 26) — требуется mesh-плагину.
- BLE между устройствами — courier-транспорт; для него Wi-Fi Direct снижает
  задержки при большом числе хопов.
